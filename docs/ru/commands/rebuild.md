# mip rebuild

::: callout info "Что это?" icon:wrench
`mip rebuild` повторно выполняет скрипты сборки для пакетов, которые уже установлены в глобальном хранилище. Это полезно после обновления Node.js, смены платформы или когда нужно перекомпилировать native (C++) аддоны — без повторной загрузки всего пакета.
:::

## Синтаксис

```bash
mip rebuild [packages...] [options]
```

## Опции

| Флаг | Описание |
|------|----------|
| `--force`, `-f` | Принудительная пересборка, даже если у пакета нет скриптов сборки (используется скрипт `rebuild` по умолчанию) |
| `--dry-run` | Симуляция процесса пересборки без реального запуска скриптов |
| `--quiet` | Подавить весь вывод, кроме ошибок и итоговой сводки |
| `--script <name>` | Запустить указанный скрипт вместо автоопределения (например, `--script build`) |

## Логика работы

1. **Чтение lock-файла** — команда читает `mip-lock.yml` (или `mip-lock.json` как запасной вариант). Если ни один не найден — выполнение прекращается.

2. **Определение целевых пакетов** — если имена пакетов не указаны, пересобираются **все** пакеты из lock-файла. Можно отфильтровать конкретные пакеты, передав их имена:

   ```bash
   mip rebuild lodash axios
   ```

3. **Проверка наличия в хранилище** — для каждого пакета проверяется, существует ли он в глобальном хранилище (`~/.mip/store/<name>/<version>/package`). Отсутствующие пакеты пропускаются.

4. **Определение скрипта сборки** — команда читает `package.json` из хранилища и ищет скрипты в следующем порядке:

   | Приоритет | Имя скрипта | Назначение |
   |-----------|-------------|------------|
   | 1 | `install` | Пост-установочный скрипт (наиболее частый для native-модулей) |
   | 2 | `rebuild` | Явный скрипт пересборки |
   | 3 | `preinstall` | Хук перед установкой |
   | 4 | `build` | Общий скрипт сборки |

   Если ни один из них не найден и флаг `--force` не установлен, пакет пропускается.

5. **Запуск скрипта** — скрипт выполняется через `npm run <script>` в директории пакета внутри хранилища. Устанавливаются следующие переменные окружения:

   | Переменная | Значение |
   |------------|----------|
   | `MIP_REBUILD` | `true` |
   | `MIP_PACKAGE_NAME` | имя пакета |
   | `MIP_PACKAGE_VERSION` | версия пакета |

   Используется локальная директория `.npm-cache`, чтобы не засорять глобальный кэш npm.

6. **Итоговая сводка** — после обработки всех пакетов выводится:

   ```
   ✅ Done. Rebuilt: 5, Skipped: 2, Errors: 0.
   ```

## Примеры

::: tabs
== tab "Пересборка всех пакетов"
```bash
mip rebuild
```

Пересобирает каждый пакет из `mip-lock.yml`, у которого есть скрипт сборки.

**Вывод:**
```
🔨 Rebuilding 8 package(s)...

🔧 Rebuilding "lodash@4.17.21" (install)...
✅ Rebuilt: lodash@4.17.21

🔧 Rebuilding "node-gyp@9.3.0" (install)...
✅ Rebuilt: node-gyp@9.3.0

⚠️ Package "express@4.18.2" has no build scripts. Skipping.

✅ Done. Rebuilt: 2, Skipped: 1, Errors: 0.
```
:::

== tab "Пересборка конкретных пакетов"
```bash
mip rebuild node-gyp bcrypt
```

Пересобирает только указанные пакеты. Неизвестные или отсутствующие пакеты отмечаются и игнорируются.

**Вывод:**
```
🔨 Rebuilding 2 package(s)...

🔧 Rebuilding "node-gyp@9.3.0" (install)...
✅ Rebuilt: node-gyp@9.3.0

🔧 Rebuilding "bcrypt@5.1.0" (install)...
✅ Rebuilt: bcrypt@5.1.0

✅ Done. Rebuilt: 2, Skipped: 0, Errors: 0.
```
:::

== tab "Принудительная пересборка"
```bash
mip rebuild --force
```

Пересобирает все пакеты, даже те, у которых нет скриптов сборки. Для пакетов без скриптов используется npm-скрипт `rebuild` (возможно, пустой, но попытка всё равно выполняется).

**Вывод:**
```
🔨 Rebuilding 8 package(s)...

🔧 Rebuilding "lodash@4.17.21" (install)...
✅ Rebuilt: lodash@4.17.21

🔧 Rebuilding "express@4.18.2" (rebuild)...
❌ Error: express@4.18.2: command exited with code 1

✅ Done. Rebuilt: 1, Skipped: 0, Errors: 1.
```
:::

== tab "Кастомный скрипт"
```bash
mip rebuild --script build
```

Запускает скрипт `build` для каждого пакета, у которого он есть, вместо автоопределения.

**Вывод:**
```
🔨 Rebuilding 8 package(s)...

🔧 Rebuilding "lodash@4.17.21" (build)...
✅ Rebuilt: lodash@4.17.21

⚠️ Package "node-gyp@9.3.0" has no script "build"
   (use --force to run anyway)

✅ Done. Rebuilt: 1, Skipped: 1, Errors: 0.
```
:::

== tab "Пробный запуск"
```bash
mip rebuild --dry-run
```

Показывает, что было бы пересобрано, без реального выполнения.

**Вывод:**
```
🔨 Rebuilding 8 package(s)...

🔧 Would rebuild "lodash@4.17.21" (install)
🔧 Would rebuild "node-gyp@9.3.0" (install)

🔍 Dry-run complete. Would rebuild: 2, Skipped: 6.
```
:::

== tab "Тихий режим"
```bash
mip rebuild --quiet
```

Пересборка без вывода по каждому пакету. Показывается только итоговая сводка.

**Вывод:**
```
✅ Done. Rebuilt: 2, Skipped: 1, Errors: 0.
```
:::
:::

## Когда использовать rebuild

| Сценарий | Зачем `mip rebuild`? |
|----------|----------------------|
| **Обновление Node.js** | Нативные аддоны, скомпилированные под старый ABI Node.js, могут не работать. Пересборка перекомпилирует их. |
| **Смена платформы** | Переход с macOS на Linux (или наоборот) — бинарники платформозависимы. |
| **Повреждённое хранилище** | Если пакет в глобальном хранилище неполный или сломан, пересборка исправит его без повторной загрузки. |
| **Кэш CI/CD** | После восстановления хранилища из кэша пересборка гарантирует, что native-модули скомпилированы под окружение CI-раннера. |
| **После `mip dedupe`** | Дедупликация может изменить используемый физический пакет — пересборка обеспечивает консистентность. |

## Типичные ошибки

::: callout warning "❌ Пакет не найден в глобальном хранилище" icon:alert-triangle
**Проблема:** Пакет есть в `mip-lock.yml`, но его директория отсутствует в `~/.mip/store/`.

**Что происходит:** Пакет пропускается с предупреждением.

**Решение:** Запустите `mip install`, чтобы повторно загрузить пакет.
:::

::: callout danger "❌ mip-lock.yml не найден" icon:skull
**Проблема:** В текущей директории нет `mip-lock.yml` или `mip-lock.json`.

**Что происходит:** Команда немедленно завершается.

**Решение:** Запустите `mip install` или `mip genlock`, чтобы сгенерировать lock-файл, затем повторите попытку.
:::

::: callout warning "⚠️ Ошибка выполнения скрипта" icon:alert-circle
**Проблема:** Скрипт сборки завершился с ненулевым кодом возврата.

**Что происходит:** Ошибка сообщается в сводке, но команда продолжает обработку остальных пакетов.

**Решение:** Запустите `mip rebuild <pkg>` (без `--quiet`), чтобы увидеть полный вывод ошибки.
:::

::: callout info "💡 Приоритет определения скрипта сборки" icon:info
Команда проверяет скрипты в порядке: `install` → `rebuild` → `preinstall` → `build`. Выбирается **первый** найденный. Если нужно запустить конкретный скрипт, используйте `--script <name>`.
:::
